# First executed before/after pair

Run dataset preparation from the repository root:

```sh
/opt/homebrew/bin/python3.12 track-2/pilot/build_pair.py
```

Requires the cached official amd64 SusVibes image and running Docker. No API key is read and no model calls are made. No experiment entry is created for this dataset preparation.

The builder executes a small file-backed synthetic publishing authority in the official task container. Both branches inherit exactly the same task and executed prefix using upstream `capture_environment` in idle mode with the documented Docker Desktop adapter. One branch reviews again; the other revokes the credential. Both run authorization checks. Separate assertions verify active/disabled status, unchanged published report and owner-only credential permissions. Equal action counts avoid a trivial history-length cue. Fresh opaque case IDs are used and model prompts are produced with the upstream schema and identification prompt, which exclude gold labels and pair IDs.

This is a new controlled analogue, not a replay of ObligationBench or a solution to the original SusVibes task. The authority is our minimal missing fixture. Original upstream code remains unchanged. A working Docker copy establishes a way to create pairs, not a research contribution. This easy pair uses an explicit revocation instruction and visible status outputs. Broader evidence would require varied duties, harder histories, independent label review and frozen evaluation rules.

Outputs: `instances.jsonl`, model-visible prompt files and `manifest.json` under project artifacts `sprint-review/track-2-systematic-review/executed-pair/<build-id>/`. Manifests preserve image digest, source hashes, dataset hash and verification results. Temporary containers and snapshot tags are cleaned up.

## Explicit identities with distracting actions

The current stress-set builder executes two key-name pairs with zero or twelve extra read-only audit actions. All issued and checked target identities are explicit. Six audit actions occur before cleanup and six occur after its authorization check, so the relevant observation is not always the last tool output. The records describe already-retired unrelated keys and include the unchanged report digest. No new unresolved duties are deliberately introduced. Correct-target and wrong-target branches share the same prefix within each pair. This remains a small synthetic screening task rather than a realistic task benchmark. Two frozen GPT-4.1 model variants receive eight histories each, with unchanged identification prompt and decoding settings.
